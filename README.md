# GophKeeper

Клиент-серверный менеджер паролей: хранит логины/пароли, произвольные
текстовые и бинарные данные, а также данные банковских карт. Сервер — gRPC,
хранилище — PostgreSQL.

> ⚠️ Проект в разработке. Готово: регистрация/вход, полный CRUD приватных
> данных с авторизацией по JWT (сервер + CLI-клиент).
> В работе: шифрование данных (client-side), TLS.

## Требования

- Go 1.25+
- Docker (для PostgreSQL)

## Запуск сервера

**1. Поднять PostgreSQL** (задайте свой пароль вместо `<your-password>`):

```bash
docker run --name gophkeeper-pg -e POSTGRES_PASSWORD=<your-password> -e POSTGRES_DB=gophkeeper -p 5432:5432 -d postgres:17
```

Миграции накатываются автоматически при старте сервера.

**2. Задать переменные окружения** (читаются с префиксом `GOPHKEEPER_`):

```bash
# Linux / macOS
export GOPHKEEPER_DATABASE_URL="postgres://postgres:<your-password>@localhost:5432/gophkeeper?sslmode=disable"
export GOPHKEEPER_JWT_SECRET="любая-длинная-случайная-строка"
```

```powershell
# Windows (PowerShell)
$env:GOPHKEEPER_DATABASE_URL = "postgres://postgres:<your-password>@localhost:5432/gophkeeper?sslmode=disable"
$env:GOPHKEEPER_JWT_SECRET = "любая-длинная-случайная-строка"
```

> Пароль в DSN и порт должны совпадать с параметрами контейнера PostgreSQL.
> `GOPHKEEPER_JWT_SECRET` — секрет для подписи JWT-токенов; задаётся только через
> окружение, в коде не хранится.

**3. Запустить сервер:**

```bash
go run ./cmd/server
```

Остановка — `Ctrl+C` (корректное завершение). По умолчанию сервер слушает `:8080`.

## Переменные окружения

| Переменная                | Обязательна | По умолчанию | Описание                     |
|---------------------------|-------------|--------------|------------------------------|
| `GOPHKEEPER_DATABASE_URL` | да          | —            | DSN подключения к PostgreSQL |
| `GOPHKEEPER_JWT_SECRET`   | да          | —            | секрет для подписи JWT       |
| `GOPHKEEPER_GRPC_ADDRESS` | нет         | `:8080`      | адрес gRPC-сервера           |
| `GOPHKEEPER_LOGGER_LEVEL` | нет         | `info`       | уровень логирования          |

## Клиент

CLI-клиент подключается к серверу по gRPC. После входа JWT-токен сохраняется
в `~/.gophkeeper/token` и автоматически прикладывается к защищённым запросам.

### Команды аутентификации

- `register --login <логин>` — регистрация нового пользователя
- `login --login <логин>` — вход
- `version` — версия и дата сборки

Пароль запрашивается интерактивно (ввод скрыт), не передаётся флагом.

### Команды работы с данными

Требуют предварительного входа (используют сохранённый токен).

- `add --type <тип> --data <данные> --meta <описание>` — добавить запись
- `list` — показать все записи
- `get --id <id>` — получить запись по id
- `delete --id <id>` — удалить запись

Тип записи (`--type`): `credentials`, `text`, `binary`, `card`.

### Флаги

- `--address` — адрес gRPC-сервера, по умолчанию `127.0.0.1:8080`
- `--login` — логин пользователя (для register/login)
- `--type`, `--data`, `--meta` — параметры записи (для add)
- `--id` — идентификатор записи (для get/delete)

### Пример полного цикла

```bash
# регистрация и вход
go run ./cmd/client register --login ivan
go run ./cmd/client login --login ivan

# работа с данными
go run ./cmd/client add --type text --data "секретная заметка" --meta "личное"
go run ./cmd/client list
go run ./cmd/client get --id <id-из-list>
go run ./cmd/client delete --id <id-из-list>
```

## Архитектурные решения

- **Протокол** — gRPC + Protocol Buffers.
- **Слоистая архитектура** — handler → service → storage, зависимости через
  интерфейсы на границах слоёв.
- **Аутентификация** — пароли хешируются (bcrypt), доступ по JWT (HS256).
  Проверку токена и извлечение пользователя выполняет unary-интерцептор.
- **Синхронизация** — клиент получает актуальное состояние
  через `list`, локальный кэш данных не ведётся (в файле хранится только токен).
- **Удаление** — мягкое (soft delete): записи помечаются удалёнными.
- **Конкурентное редактирование** — оптимистичная блокировка по версии записи:
  клиент присылает версию, полученную при чтении; при рассинхроне сервер
  отвечает конфликтом.
